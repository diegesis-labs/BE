# 용어집

이 문서는 백엔드 문서에 등장하는 용어의 뜻을 한곳에 모아 둔 문서입니다. 다른 문서에서 낯선 용어를 만나면 먼저 이 문서를 확인해 주세요. 그리고 새 용어가 생기면 다른 문서에 풀이를 적지 말고 이 문서에 추가해 주세요.

## 표기와 관련된 용어

| 용어 | 뜻 |
| --- | --- |
| 번호 | API와 산출물 묶음, 데이터베이스의 필드에 담는 순번 가운데 1부터 세는 것입니다. 챕터 번호와 책의 버전 번호가 여기에 해당합니다. |
| 인덱스 | API와 산출물 묶음, 데이터베이스의 필드에 담는 순번 가운데 0부터 세는 것입니다. 문장 인덱스가 여기에 해당합니다. 1부터 세는 번호와 헷갈리지 않도록 "번호"라고 부르지 않습니다. |

## 책과 관련된 용어

| 용어 | 뜻 |
| --- | --- |
| 문장 인덱스 | 책 한 권의 모든 문장에 첫 문장부터 차례대로 붙인 인덱스입니다. 챕터가 바뀌어도 이어지며, 0부터 시작합니다. 화면 크기나 글꼴과 무관하게 책 속 위치를 가리킬 수 있어서, 프론트엔드와 백엔드가 위치를 주고받는 공통 단위로 씁니다. |
| 트리거 문장 | 소설의 분위기가 바뀌기 시작하는 지점의 첫 문장입니다. 앞뒤 문장들의 의미가 얼마나 달라지는지를 계산해서 찾아내며, 이 계산은 AI 레포가 미리 수행합니다. |
| 장면(scene) | 어떤 트리거 문장부터 다음 트리거 문장 직전까지 이어지는 문장들의 묶음입니다. 하나의 장면은 하나의 분위기를 가진다고 보고, 음악은 장면 단위로 고릅니다. |
| 캡션(caption) | 장면에 어울리는 음악을 짧은 영어 문장으로 묘사한 글입니다. 예를 들어 "slow, melancholic solo piano"와 같은 글이며, 언어 모델이 장면을 읽고 작성합니다. 소설 문장을 그대로 쓰지 않고 캡션을 거치는 까닭은, 임베딩 모델이 소설 문체가 아니라 음악을 묘사하는 글로 학습되었기 때문입니다. |
| 직접 언급 장면 | 작중 인물이 듣거나 이야기하는 특정 곡의 제목이나 아티스트가 본문에 실제로 적혀 있는 장면입니다. |
| 지정 곡 | 직접 언급 장면에서 언급된 바로 그 곡이 우리 음악 목록에 있을 때, AI 레포가 그 장면에 연결해 둔 곡입니다. |

## 음악과 관련된 용어

| 용어 | 뜻 |
| --- | --- |
| 곡(track) | 음원 파일 하나에 해당하는 음악 한 곡입니다. |
| 구간(segment) | 곡 하나를 수십 초 길이로 잘라 낸 조각입니다. 한 곡 안에서도 분위기가 달라질 수 있으므로, 곡 전체가 아니라 구간마다 따로 임베딩을 만듭니다. |
| 오브젝트 저장소 | 음원처럼 용량이 큰 파일을 보관하고, 인터넷 주소로 내려받을 수 있게 해 주는 저장 서비스입니다. Google Cloud Storage나 Amazon S3가 여기에 해당합니다. |
| 서명된 주소(presigned URL) | 비공개로 보관된 파일을 정해진 시간 동안만 받을 수 있게 해 주는 임시 주소입니다. 주소 안에 만료 시각과 위조를 막는 서명이 들어 있어서, 시간이 지나거나 주소를 고치면 쓸 수 없습니다. 백엔드가 곡을 골라 줄 때마다 새로 발급합니다. |

## 추천과 관련된 용어

| 용어 | 뜻 |
| --- | --- |
| 임베딩(embedding) | 글이나 소리의 의미를 수백 개의 숫자로 이루어진 목록으로 바꾼 것입니다. 의미가 비슷한 대상일수록 숫자 목록도 서로 비슷해지도록 만들어집니다. |
| 벡터(vector) | 임베딩을 이루는 숫자 목록 그 자체를 가리키는 말입니다. 이 문서들에서는 임베딩과 같은 뜻으로 씁니다. |
| 임베딩 모델 | 글이나 소리를 임베딩으로 바꿔 주는 AI 모델입니다. 우리는 글과 음악을 같은 기준의 숫자 목록으로 바꿔 주는 모델인 MuQ-MuLan과 LAION-CLAP을 씁니다. 서로 다른 모델이 만든 임베딩끼리는 비교할 수 없습니다. |
| 차원 | 임베딩 하나를 이루는 숫자의 개수입니다. MuQ-MuLan과 LAION-CLAP은 모두 512차원입니다. |
| 벡터 검색 | 어떤 벡터와 가장 비슷한 벡터들을 데이터베이스에서 찾아내는 일입니다. 우리 서비스에서는 장면의 벡터와 가장 비슷한 음악 구간의 벡터를 찾는 데 씁니다. |
| 코사인 유사도 | 두 벡터가 얼마나 비슷한 방향을 가리키는지를 나타내는 값입니다. 1에 가까울수록 비슷하다는 뜻입니다. |
| top-k | 비슷한 순서로 정렬했을 때 위에서부터 k개를 뜻합니다. k는 설정값으로 정하는 개수입니다. |
| 후보 목록 | 위치 알림에 대한 응답으로 백엔드가 내주는, 한 장면에 어울리는 음악 구간들의 목록입니다. 최대 k개이며, 지정 곡이 있으면 맨 앞에 둡니다. 이 가운데 무엇을 틀지는 프론트엔드가 정합니다. |
| 샘플링 | 여러 후보 가운데 하나를 무작위로 뽑는 일입니다. 프론트엔드가 후보 목록에서 재생할 구간을 고를 때 하며, 항상 1등만 고르지 않기 때문에 같은 장면을 다시 읽어도 다른 곡이 나올 수 있습니다. |
| 선곡 기록(recommendation) | 어떤 사용자에게, 어떤 장면에서, 어떤 임베딩 모델로, 어떤 구간을 후보로 내주었는지를 남긴 기록 한 건입니다. 후보 하나가 기록 한 건이며, 같은 후보 목록에 담긴 기록들은 하나의 목록으로 묶입니다. |
| 싫어요 | 재생 중인 구간이 마음에 들지 않을 때 사용자가 누르는 버튼, 또는 그 반응입니다. 싫어요를 누른 구간은 그 사용자에게 다시 후보로 나오지 않으며, 프론트엔드는 음악을 멈추지 않고 후보 목록의 다른 구간을 틉니다. 일시정지는 싫어요로 보지 않습니다. |

## 평가와 관련된 용어

| 용어 | 뜻 |
| --- | --- |
| 평가 라벨 | 장면과 음악 구간에 붙이는 네 값(`valence`, `arousal`, `tags`, `gems`)입니다. 곡을 고를 때에는 쓰지 않고, 고른 곡이 장면에 맞았는지를 채점할 때 정답으로 씁니다. AI 레포가 만들어 산출물 묶음에 담습니다. |
| V-A | valence와 arousal을 함께 부르는 말입니다. valence는 얼마나 기분이 좋은지를, arousal은 얼마나 긴장되고 흥분되는지를 나타내며, 둘 다 -1에서 1 사이의 값입니다. 장면의 V-A와 고른 구간의 V-A가 가까울수록 분위기가 맞는 곡으로 봅니다. |
| 태그(tag) | 분위기를 나타내는 낱말입니다. 예를 들면 `calm`, `melancholic`과 같습니다. 장면과 고른 구간에 같은 태그가 있는지를 보조 지표로 봅니다. |
| GEMS | 음악을 듣는 사람이 느끼는 감정을 아홉 가지 차원으로 나눈 심리학 척도(Geneva Emotional Music Scale)입니다. 차원은 경이, 초월, 다정, 그리움, 평온, 힘, 즐거운 활력, 긴장, 슬픔이며, 장면과 고른 구간이 같은 차원에 속하는지를 보조 지표로 봅니다. |

## 시스템과 관련된 용어

| 용어 | 뜻 |
| --- | --- |
| 오프라인 배치 | 사용자의 요청을 받는 그 순간에 처리하지 않고, 미리 한꺼번에 계산해 두는 작업 방식입니다. |
| 런타임 | 서비스가 실제로 켜져서 사용자의 요청을 처리하고 있는 동안을 가리킵니다. |
| 모델 서빙 | AI 모델을 서버에 올려 두고, 요청이 올 때마다 모델을 실행해서 결과를 돌려주는 일입니다. |
| 산출물 묶음(bundle) | AI 레포가 분석을 마치고 내놓는 결과 파일들을 zip 파일 하나로 묶은 것입니다. 책 묶음과 음악 묶음 두 종류가 있습니다. |
| 적재 | 산출물 묶음의 내용을 검사한 다음 데이터베이스에 넣는 일입니다. |
| 허용 목록 | 서비스에 들어올 수 있는 사람들의 Google 이메일 주소 목록입니다. 목록에 없는 계정은 로그인을 해도 서비스를 쓸 수 없습니다. 데이터베이스의 `allowed_emails` 테이블에 있으며, 사람마다 `user`나 `admin`의 역할이 붙습니다. |
| 보호된 경로 | 로그인한 사용자나 관리자만 부를 수 있는 API 경로입니다. 헬스체크, 로그인과 로그아웃, API 문서의 경로를 뺀 모든 경로가 여기에 해당합니다. |
| 관문 | 보호된 경로의 요청마다 로그인 상태, 허용 목록, 관리자 권한을 차례로 확인하고, 통과하지 못하면 401이나 403으로 거절하는 백엔드의 확인 절차입니다. |
| 돌아올 주소(redirect URI) | 사용자가 Google에서 로그인을 마친 뒤 Google이 브라우저를 돌려보내는 주소입니다. Google 콘솔에 미리 등록한 주소로만 돌려보냅니다. |
| PKCE | 로그인을 시작할 때 만든 비밀값(`code_verifier`)으로, Google이 돌려준 `code`를 그 로그인을 시작한 브라우저에 묶는 방법입니다. 인가 주소에는 비밀값의 해시(`code_challenge`)만 보내고, `code`를 교환할 때 비밀값을 보냅니다. 그래서 다른 곳에서 새어 나온 `code`는 쓸 수 없습니다. |
| nonce | 로그인을 시작할 때 만들어 인가 주소에 담는 임의의 값입니다. Google은 이 값을 ID 토큰에 그대로 담아 돌려주며, 백엔드는 두 값이 같은지 확인해 그 ID 토큰이 이 로그인을 위해 발급된 것인지 판단합니다. |
| Google 계정 식별자(`sub`) | Google이 계정마다 붙이는, 바뀌지 않고 다시 쓰이지 않는 식별자입니다. 이메일 주소는 바뀌거나 다른 계정에 다시 쓰일 수 있으므로, 백엔드는 이메일과 이 값을 한 쌍으로 묶어 사람을 식별합니다. `users.google_sub`에 저장합니다. |
| 출처 확인 | 상태를 바꾸는 요청(`GET`, `HEAD`, `OPTIONS`가 아닌 요청)의 `Origin` 헤더가 프론트엔드의 주소와 같은지 확인하는 백엔드의 절차입니다. 다른 사이트의 화면이 사용자의 쿠키를 실어 요청을 보내는 것(CSRF)을 막습니다. |
| 대역 서버 | 로컬 로그인 점검에서 프론트엔드의 개발 서버를 흉내 내는 작은 서버입니다. 프론트엔드의 주소에서 `/api` 요청을 Host를 바꿔 백엔드로 넘기고, 그 밖의 경로에는 빈 화면을 냅니다. |
| 로컬 로그인 점검 | 백엔드 담당자가 프론트엔드 레포 없이 로컬에서 실제 Google 계정으로 로그인과 로그아웃을 확인하는 절차입니다. 사람은 Playwright가 연 브라우저에서 Google 계정을 고르고, 점검 스크립트는 대역 서버를 띄우고 시점마다 테이블의 상태를 출력합니다. |
| 로그인 상태(login session) | 사용자가 Google 로그인에 성공한 때부터 로그아웃하거나 기한이 지날 때까지 유지되는 인증 상태입니다. 브라우저의 쿠키와 `login_sessions` 테이블로 관리합니다. |
| 포트(port) | 백엔드의 핵심 로직이 바깥 세계(데이터베이스, 저장소, 로그인 서비스 등)에 기대하는 기능을 적어 둔 약속입니다. 코드에서는 메서드 이름과 입출력만 선언한 인터페이스로 표현합니다. |
| 어댑터(adapter) | 포트의 약속을 특정 기술로 실제로 구현한 코드입니다. 예를 들어 "벡터 검색" 포트를 PostgreSQL로 구현한 코드가 어댑터입니다. 어댑터만 바꾸면 핵심 로직을 고치지 않고도 기술을 교체할 수 있습니다. |
| SPA | 브라우저가 화면 전체를 한 번 내려받은 뒤, 페이지를 옮길 때마다 서버에서 새 화면을 받지 않고 스스로 화면을 바꾸는 웹 앱 방식입니다. 우리 프론트엔드가 이 방식입니다. |

## 개발 절차와 관련된 용어

| 용어 | 뜻 |
| --- | --- |
| harness | 에이전트에게 구현을 맡길 때 쓰는 틀입니다. 작업을 작은 단위로 나누어 순서대로 실행하게 하고, 규칙을 어기는 행동을 막고, 결과를 다시 판정합니다. 절차는 [HARNESS.md](HARNESS.md)에 있습니다. |
| 에이전트 세션 | Claude Code를 한 번 실행해서 끝날 때까지의 대화 하나입니다. 에이전트 세션은 서로의 대화 내용을 알지 못합니다. |
| 헤드리스 실행 | 사람이 지켜보지 않는 상태로 에이전트 세션을 띄워, 주어진 지시 하나를 끝까지 수행하게 하는 방식입니다. |
| Epic | 하나의 목표를 이루는 구현 작업의 묶음입니다. GitHub 이슈 하나, phase 하나와 짝을 이룹니다. |
| Story | Epic을 이루는 기능 단위입니다. 여러 개의 Task로 이루어집니다. |
| 테스트 케이스(TC) | Story가 지켜야 하는 것 하나를 확인하는 항목입니다. 확인하는 상황과 합격 기준을 함께 적습니다. |
| phase | Epic 하나를 harness로 실행하는 단위입니다. `phases/` 아래에 폴더 하나로 기록됩니다. |
| step | phase를 이루는 실행 단위입니다. step 하나를 에이전트 세션 하나가 맡습니다. |
| 완료 조건(AC) | step이 끝났는지를 판정하는 조건입니다. 실행할 수 있는 명령으로 적으며, 명령이 성공으로 끝나면 통과입니다. |
| 반증 조건 | 테스트가 반드시 걸러 내야 하는 틀린 구현을 적은 것입니다. 그 틀린 구현으로도 테스트가 통과한다면 테스트가 잘못된 것입니다. |
| RED 커밋 | 구현하기 전에, 실패하는 테스트만 담아서 남기는 커밋입니다. 테스트를 구현보다 먼저 썼다는 증거가 됩니다. |
| MANUAL 점검표 | 테스트로는 확인할 수 없어서 사람이 직접 확인해야 하는 항목의 목록입니다. phase마다 `MANUAL.md` 파일로 둡니다. |
| 훅(hook) | 에이전트가 파일을 고치거나 명령을 실행하려 할 때, 또는 턴을 끝내려 할 때 Claude Code가 자동으로 실행하는 스크립트입니다. |
| 가드 | 훅 가운데 에이전트의 행동을 검사해서 규칙에 어긋나면 막는 스크립트입니다. |
| 리뷰 라운드 | 리뷰를 한 번 하고 그 결과를 처분하는 한 차례를 가리킵니다. 중대한 결함을 고쳤으면 다음 라운드에서 다시 리뷰합니다. |
| 리뷰 처분 | 리뷰가 찾은 결함을 하나씩 확인해서, 고치거나 근거를 들어 기각하거나 사람의 판단으로 넘기는 일입니다. |
| worktree | 한 저장소의 브랜치 하나를 별도의 폴더에 펼쳐 놓은 것입니다. 여러 작업을 서로 섞이지 않게 동시에 진행할 수 있습니다. |
| Orca | 에이전트 세션과 worktree를 관리하는 데스크톱 앱입니다. Orca가 만든 worktree가 앱의 사이드패널에 보입니다. |
| CI | 코드가 올라올 때마다 검사와 테스트를 자동으로 돌리는 것입니다. 이 레포에서는 GitHub Actions로 돌립니다. |
| ruleset | GitHub의 브랜치에 거는 규칙의 묶음입니다. PR을 거치지 않은 병합이나 검사가 실패한 병합을 막을 수 있습니다. |
| 스모크 테스트(smoke test) | 전체를 실제로 띄운 뒤 가장 기본적인 동작만 빠르게 확인하는 테스트입니다. 이 레포에서는 `scripts/compose-smoke.sh`가 이 일을 합니다. |
| testcontainers | 테스트가 시작될 때 데이터베이스 같은 컨테이너를 실제로 띄우고, 테스트가 끝나면 지우는 라이브러리입니다. |
| fixture | 테스트에 필요한 준비물을 만들어 넘겨주고, 테스트가 끝나면 정리하는 pytest의 함수입니다. 예를 들어 `tests/conftest.py`의 fixture는 통합 테스트용 데이터베이스를 띄워서 그 주소를 테스트에 넘깁니다. |
| actionlint | GitHub Actions의 workflow 파일에서 문법 오류와 흔한 실수를 찾아 주는 검사 도구입니다. 이 레포에서는 테스트가 `.github/workflows/`의 파일에 이 도구를 실행합니다. |

## 실행 환경과 관련된 용어

| 용어 | 뜻 |
| --- | --- |
| 컨테이너 이미지 | 프로그램과 그 프로그램이 실행되는 데 필요한 것을 모두 담은 꾸러미입니다. 이미지를 실행한 것을 컨테이너라고 부릅니다. |
| Docker Compose | 여러 컨테이너를 한 파일(`compose.yaml`)에 적어 두고 함께 띄우고 내리는 도구입니다. |
| 빌드 맥락(build context) | 이미지를 빌드할 때 Docker에 넘기는 파일의 묶음입니다. `Dockerfile`은 이 묶음 안의 파일만 이미지에 복사할 수 있으며, `.dockerignore`에 적은 파일은 이 묶음에서 빠집니다. |
| Docker builder | Docker가 이미지를 빌드할 때 쓰는 빌드 엔진과 그 설정입니다. 어떤 builder를 쓰느냐에 따라 `docker build`로 만든 이미지가 로컬 이미지 저장소에 바로 실리기도 하고 그렇지 않기도 합니다. |
| 마이그레이션(migration) | 데이터베이스의 구조를 바꾸는 작업을 순서대로 기록한 스크립트입니다. 이 레포에서는 Alembic으로 관리합니다. |
| 헬스체크(health check) | 서버가 살아 있는지 확인하는 요청입니다. 이 레포에서는 `GET /api/health`입니다. |
| 준비 상태 확인(readiness check) | 서버가 요청을 처리할 준비가 되었는지를 데이터베이스와의 연결까지 포함해서 확인하는 요청입니다. 서버가 살아 있는지만 보는 헬스체크보다 넓게 확인합니다. |
| CPU 아키텍처 | 컨테이너 이미지가 실행되는 CPU의 종류입니다. Apple Silicon의 Mac은 `arm64`이고, Windows와 Intel 기반의 컴퓨터, 그리고 대부분의 서버는 `amd64`입니다. 이미지는 아키텍처마다 따로 빌드합니다. |

> "세션"이라는 말은 여러 가지 뜻으로 읽힐 수 있습니다. 따라서 문서에서는 "세션"을 단독으로 쓰지 않습니다. 사용자의 인증 상태는 "로그인 상태"라고 쓰고, 에이전트의 대화 하나는 "에이전트 세션"이라고 씁니다.
