# 차원별 리뷰 브리프

각 절을 그대로 해당 sub-agent 프롬프트에 넣는다. "전례"는 이 프로젝트에서 **실제로 뚫린** 자리다 — 같은 종류를 먼저 찾아라.

전례는 처음에는 비어 있다. 리뷰 처분(`review-fix` 스킬)이 라운드마다 실제로 고친 critical·major의 유형을 한 줄씩 더한다. 다른 프로젝트의 사례를 여기에 옮겨 적지 마라 — 이 코드에서 일어나지 않은 일은 전례가 아니다.

---

## correctness — 로직/버그

diff의 코드가 **자기가 하려는 일을 실제로 하는가**를 본다. 문서와의 대조는 behavioral의 것이고, 너는 코드 안에서 닫히는 오류를 본다.

**먼저 볼 곳**

- **실패 경로** — 정상 흐름은 이미 테스트가 지킨다. 벡터 검색이 후보를 하나도 돌려주지 않을 때, 오브젝트 저장소가 응답하지 않을 때, 묶음의 파일 하나가 깨졌을 때, Google이 오류를 돌려줄 때 무엇이 되는가. 특히 **아무것도 안 되고 조용히 넘어가는 자리**
- **에러 삼킴** — `except Exception: pass`, 로그만 찍고 정상 응답을 돌려주는 실패, `await`하지 않은 코루틴, 참조를 잡지 않아 사라지는 `asyncio.create_task`. 사용자는 곡이 안 나오는 이유를 모르고, 평가 기록은 빠진다
- **경합** — `await` 사이에 상태가 바뀔 수 있는가. 같은 사용자의 위치 알림 두 개가 동시에 와서 선곡 기록이 두 줄 생기는가. 쉬는 시간을 "확인한 뒤 쓰는" 사이에 다른 요청이 끼어드는가. 같은 묶음을 동시에 두 번 올리면 어떻게 되는가
- **전부/일부** — `asyncio.gather`는 하나가 깨지면 예외를 던진다. 부분 성공이 정상인 자리에 쓰였는가. 반대로 전부 아니면 전무여야 하는 자리(묶음 적재)가 중간까지만 들어간 채 남는가 — 트랜잭션 경계를 보라
- **순수 함수 불변식** — 인자를 그 자리에서 변형(mutate)하는가. 같은 입력에 같은 출력인가. 무작위가 들어가는 함수는 난수원을 주입받는가
- **경계값** — 빈 후보 목록(전부 중단한 곡), `top_k`가 후보 수보다 큼, 샘플링 온도 0, 문장 번호 0, 책의 마지막 문장, 장면이 하나뿐인 챕터. off-by-one
- **시각과 단위** — 시간대 없는(naive) `datetime`과 시간대 있는 것의 혼용, 초와 밀리초(`_ms`)의 혼용, 쉬는 시간이 끝나는 정확한 순간의 판정(이상/초과)
- **벡터** — 서로 다른 임베딩 모델의 벡터를 비교하는가. 차원이 다른 벡터가 같은 쿼리에 들어가는가. 조건으로 거른 뒤 k개보다 적게 돌아오는 경우를 다루는가
- **비동기 경로의 블로킹** — `async def` 안에서 동기 파일 I/O, 동기 DB 드라이버, 큰 zip 압축 해제, `time.sleep`을 그대로 부르는가
- **파생값 이중화** — 계산해야 할 값을 저장해 두고 한쪽만 갱신하는가

**전례**

- compose의 db healthcheck가 `pg_isready`에 호스트를 주지 않아 유닉스 소켓만 봤다. pgvector 이미지의 첫 초기화 중 임시 서버(`listen_addresses=''`)가 뜬 순간 healthy가 되어, TCP로 붙는 migrate가 거부당할 수 있었다(Epic 0 COR-1). `depends_on: service_healthy`가 기대는 healthcheck가 뒤따르는 서비스와 같은 경로(TCP)로 확인하는지 본다.

**보지 않는 것** — 문서/요구사항 대조(behavioral), 테스트가 무엇을 단언하는가(test coverage), 파일 배치와 규칙 위반(architecture).

## security — 주입/권한/인증/시크릿

이 서비스의 경계는 **Google 로그인과 허용 목록**이다. 테스트용 책에 저작권이 있는 소설이 들어 있어서, 허용 목록 밖의 계정이 본문이나 음원에 닿는 경로가 하나라도 있으면 다른 것이 다 맞아도 실패다(`docs/ARCHITECTURE.md` 1절, `docs/DECISIONS.md` D-06). 그런 경로는 발동 조건이 좁아 보여도 critical이다.

**먼저 볼 곳**

- **접근 관문** — 헬스체크와 로그인 경로를 뺀 **모든** 경로가 로그인 상태와 허용 목록을 확인하는가(`docs/API.md` 3절의 표와 대조). 새 라우터가 관문 없이 등록됐는가. 허용 목록에서 뺀 계정의 기존 로그인 상태가 계속 통하는가. 확인이 로그인할 때 한 번뿐인가, 요청마다인가
- **본문이 새는 옆길** — 챕터 본문 경로 말고 다른 곳에 문장이 실려 나가는가. 에러 응답의 `detail`, 로그, 선곡 응답의 부가 필드, 평가 자료 내보내기, 자동 생성되는 API 문서의 예시
- **관리자 판정** — 관리자 전용 경로(`/api/admin/*`)의 판정을 서버가 저장된 값으로 하는가. 요청이 주장하는 값(헤더, 본문, 쿼리)을 믿는가
- **쿠키와 로그인 흐름** — 쿠키의 `HttpOnly`·`Secure`·`SameSite`, OAuth `state` 검증, 로그인 뒤 돌아갈 주소를 요청에서 받아 그대로 쓰는가(열린 리디렉션), CORS가 자격 증명을 허용하면서 출처를 `*`로 두는가
- **서명된 주소** — 음원은 서명된 주소로만 받는다(D-21). 만료 시간이 있는가, 서명 키의 기본값이 로컬 밖에서 쓰일 수 있는가, 로컬 개발용 음원 경로가 `APP_ENV`가 로컬이 아닐 때도 열리는가, 오브젝트 키나 파일 경로를 요청의 문자열로 조립하는가(`..`·절대경로)
- **묶음 적재** — zip 안의 경로가 압축을 풀 폴더 밖을 가리키는가(zip slip). 압축을 풀기 전에 크기 상한을 보는가, 푼 뒤의 크기는(zip 폭탄). `manifest.json`의 값(파일 이름, 모델 이름, ID)이 파일 경로나 SQL 식별자로 쓰이는가
- **SQL** — 문자열 결합 대신 파라미터 바인딩인가. 식별자(테이블·인덱스 이름)를 동적으로 만드는 자리가 있는가 — 임베딩 모델을 등록하며 인덱스를 만드는 자리(`docs/ARCHITECTURE.md` 7절)에 묶음이 준 모델 이름이 그대로 들어가는가
- **시크릿** — 하드코딩된 키·OAuth 자격·저장소 자격·DB 주소가 코드나 diff, 테스트 픽스처, `.env.example`에 있는가
- **개인정보** — 이메일이 필요한 범위를 넘어 로그에 남거나 응답에 실리는가. 다른 사용자의 기록(중단한 곡, 선곡 설정, 반응)을 볼 수 있는가 — 조회 쿼리가 현재 사용자로 걸러지는가

**전례**

- 아직 없다.

**보지 않는 것** — 일반 버그(correctness), 디렉터리 구조(architecture). 실제 공격 경로를 그릴 수 없는 "이론적으로 위험" 항목은 minor 이하로 두거나 버려라.

## architecture — 구조적 일관성

판정 기준이 문서에 **명시돼 있다.** 상상하지 말고 대조하라. `docs/DEVELOPMENT.md`의 "반드시 지킬 규칙"과 그 표가 가리키는 문서(`docs/ARCHITECTURE.md` 8절, `docs/CONFIGURATION.md` 1절, `docs/API.md` 2절), 그리고 `docs/ADR.md`가 기준이다.

**먼저 볼 곳**

- **의존 방향** — 기능 폴더 안에서 `router` → `service` → `repository` 순서로만 import하는가. 거꾸로 가는 import가 있는가. **ruff와 pyright는 이것을 잡지 않으니 import 줄을 눈으로 확인하라**
- **service의 기술 무지** — `service.py`가 `sqlalchemy`, `fastapi`, `authlib`, `app.adapters`를 import하는가. service는 포트에만 의존하고 특정 기술의 이름을 알지 못해야 한다
- **포트 우회** — 바깥 세계와 닿는 호출(벡터 검색, 오브젝트 저장소, Google, 묶음 읽기)이 포트 없이 박혔는가. 어댑터 구현이 `app/adapters/` 밖에 있는가. 어댑터 주입이 `app/main.py`가 아닌 곳에서 일어나는가. 포트 정의가 `app/core/` 밖에 있는가
- **기능 폴더 사이** — 한 기능 폴더가 다른 기능 폴더의 `repository`나 `models`를 직접 import하는가. 다른 기능이 필요하면 그 기능의 `service`를 거치는가
- **설정** — 설정 클래스 밖에서 `os.environ`·`os.getenv`를 읽는가. 새 설정값이 설정 클래스, `docs/CONFIGURATION.md` 3절, `.env.example` 세 곳에 모두 있는가(`docs/CONFIGURATION.md` 5절)
- **API 공통 규칙** — 응답 필드가 `snake_case`인가, 길이와 위치가 `_ms`로 끝나는 밀리초 정수인가, 시각이 UTC ISO 8601인가, 에러가 `{code, message, detail}` 형식인가. FastAPI의 기본 검증 오류(422와 그 본문)가 그대로 나가는가. `docs/API.md` 3절에 없는 경로가 생겼는가
- **데이터 모델** — `models.py`가 `docs/ARCHITECTURE.md` 6절과 맞는가. 모델을 바꿨는데 마이그레이션이 없거나, 이미 커밋된 마이그레이션을 고쳐 썼는가. 벡터 컬럼의 차원을 모델 하나에 맞춰 고정했는가
- **확장 구조** — 새 선곡 방식이 `RecommendationStrategy` 구현으로 들어갔는가, `if` 분기로 박혔는가. 임베딩 모델의 이름이 코드에 상수로 들어갔는가(모델은 코드가 아니라 등록된 데이터다)
- **ADR 이탈** — ADR이 정하지 않은 의존성이 추가됐는가. 서버에서 AI 모델을 실행하는 코드가 들어왔는가(ADR-003). 동기 DB 드라이버가 들어왔는가
- **검사 후퇴** — `# type: ignore`, `# noqa`, `Any`, `cast`가 새로 들어왔는가. `pyproject.toml`의 ruff·pyright·pytest 설정이 느슨해졌는가(규칙 제거, 제외 경로 추가)
- **구조 대응** — `tests/`가 `app/`과 같은 구조인가. 파일이 `docs/ARCHITECTURE.md` 8절의 다섯 파일 역할에 맞게 놓였는가(판정 로직이 `schemas.py`나 `models.py`에 들어가 있지 않은가)
- **문서** — 같은 정보가 두 문서에 적혔는가(D-20). `docs/GLOSSARY.md`에 없는 새 용어가 문서나 API 필드에 들어왔는가(D-17). "세션"이 단독으로 쓰였는가

**전례**

- 에러 처리기의 상태→code 표(`_HTTP_ERRORS`)가 API.md 2.3절 표의 일부(401·404·405)만 옮겨, 표에 있는 400·500의 HTTP 예외가 `HTTPStatus`의 이름(`BAD_REQUEST`·`INTERNAL_SERVER_ERROR`)으로 나갔고 이름 없는 상태(499)에서는 처리기가 터졌다(Epic 0 ARC-1). 문서의 표를 옮긴 코드는 행을 하나씩 대조한다.
- 처리기가 검증 실패를 400으로 바꿨지만 OpenAPI에는 FastAPI 기본의 422와 `HTTPValidationError`가 남아, 프론트엔드가 타입을 만드는 문서와 실제 응답이 어긋났다(Epic 0 ARC-2). 응답을 바꾸는 처리기는 `/api/openapi.json`도 함께 바꾸는지 본다.

**보지 않는 것** — 로직 오류(correctness), 요구사항 충족(behavioral). 문서에 근거가 없는 취향("이 파일은 더 잘게 나누는 게 좋다")은 올리지 마라.

## test coverage — 테스트 커버리지

개수와 퍼센트가 아니라 **"이 테스트가 무엇을 반증하는가"**를 본다. 이 프로젝트는 하네스가 테스트와 구현을 같은 세션에서 쓰므로 **자기 채점**이다. 가짜 초록이 이 차원의 본업이다.

**먼저 볼 곳**

- **반증 조건 실행** — `phases/{task}/step*.md`의 "반증 조건"에 적힌 가짜 구현을 머릿속에서 넣어 보라. 그래도 테스트가 초록이면 **그 테스트가 틀렸다**. 이것이 이 차원의 첫 번째 작업이다
- **TC 대조** — `docs/backlog/epic-{N}/testcase.md`의 TC 번호가 실제 테스트에 있는가. **이름만 TC를 달고 단언이 다른 것을 보는 경우**를 특히 찾아라
- **가짜 초록 패턴**
  - 결과의 *크기·존재*만 단언하고 *내용*을 안 본다 (응답이 200인지만 보고 본문은 안 본다, 후보가 k개인지만 보고 중단한 곡이 빠졌는지는 안 본다)
  - 0개를 수집해도 통과한다 (빈 목록에 대한 `for`·`all()`, 매개변수가 빈 `parametrize`)
  - 가짜 어댑터가 자기 자신을 단언한다 — 테스트가 구현을 지나가지 않고 가짜가 돌려준 값을 그대로 확인한다
  - 픽스처가 너무 작아 틀린 구현도 맞는다 (후보가 하나뿐이라 아무거나 골라도 통과한다)
  - 실제 PostgreSQL과 pgvector가 필요한 경로를 다른 DB나 가짜로 대신해 놓고 통합 테스트라고 부른다
  - `skip`·`xfail`·마커 때문에 기본 실행(`scripts/check.sh`)에서 빠진다 — 초록인 것이 아니라 안 돈 것이다
  - 구현이 바뀌자 **테스트가 약화되는 방향으로** 함께 고쳐졌다 (diff에서 지워진 단언을 보라)
- **미커버 분기** — 실패 경로, 빈 입력, 허용 목록 밖의 계정, 로그인 만료, 묶음 검증의 각 항목(`docs/AI_CONTRACT.md` 5절), 같은 묶음의 재적재. 로직이 있는데 테스트가 아예 없는 파일
- **TDD 순서** — step 파일이 RED 커밋을 지시한 자리에 실제로 `test(...): RED` 커밋이 구현보다 먼저 있는가. `git log --oneline --name-only main...HEAD`로 커밋 순서를 볼 수 있다. 2차 이상이면 처분(`fix-{N}.md`)이 고쳤다는 결함에도 RED 커밋이 있는가
- **MANUAL로 떠넘긴 것** — `phases/{task}/MANUAL.md`의 항목 가운데 **단언으로 적을 수 있는 것**이 있는가. "응답이 200인지 확인", "로그에 값이 찍히는지 확인", "명령을 실행해 출력을 본다" 같은 항목은 테스트 케이스여야 한다(`.claude/commands/harness.md` D-4). 항목에 "테스트로 덮을 수 없는 이유"가 없거나, 그 이유가 가짜 어댑터나 통합 테스트로 풀리는 것이면 결함으로 올려라
- **테스트 자체의 결함** — 실제 시계·실제 네트워크·테스트 실행 순서에 의존해 느리거나 흔들리는가. 고정하지 않은 난수에 의존하는가

**전례**

- 스모크 스크립트의 다섯 확인을 늘 통과하게 망가뜨려도 `tests/infra`가 초록이었다. 테스트가 스크립트의 문자열과 compose가 실패하는 경로 하나만 봤고, 확인이 어긋날 때 0이 아닌 코드로 끝나는지는 돌려 보지 않았다(Epic 0 TST-1). 판정하는 셸 스크립트는 가짜 명령으로 정상과 확인별 실패를 모두 돌려 보는지 본다.
- 헬스체크 테스트가 "DB 오류가 500으로 새는가"만 봐서, 질의하고 예외를 삼키는 구현이 초록이었다(Epic 0 TST-2). "하지 않는다"를 단언하는 테스트는 응답이 아니라 시도 자체(소켓과 엔진의 연결, 설정 읽기)를 기록하는지 본다.

**보지 않는 것** — 구현의 버그 자체(correctness). `MANUAL.md`에서 **정말로 사람만 볼 수 있는** 항목(선곡이 어울리는지, 실제 Google 로그인, 배포 환경)과 `measure` 항목은 사람의 몫이니 "테스트가 없다"고 올리지 마라.

## behavioral — 의도 vs 실제 동작

기획·설계 문서가 **요구한 것**과 코드가 **실제로 하는 것**을 대조한다. 코드만 읽어서는 알 수 없는 차원이므로, 근거를 항상 문서의 자리(`API §4.7`, `AI_CONTRACT §5`, `ARCHITECTURE §4`, `D-12`, `ADR-005`, `S{n}.{m}`, `TC-x.x.x`)로 인용하라.

**먼저 볼 곳**

- **선언 vs 실제** — 하네스는 자기 채점이다. `phases/{task}/index.json`의 step `summary`, 커밋 메시지, 처분 기록(`fix-{N}.md`)이 **주장하는 것**을 코드에서 확인하라. "X를 만들었다"고 적혔는데 그 파일이 없거나, 있는데 배선되지 않았거나(라우터가 등록되지 않았다, 어댑터가 주입되지 않았다), 다른 것을 하는 경우가 이 차원의 고유 표면이다
- **API 형식 대조** — 이 phase가 만든 엔드포인트를 `docs/API.md` 4절의 해당 항목과 필드 하나씩 대조한다. 필드 이름, 타입, 없을 때의 값(`null`인가 빠지는가), 상태 코드, 에러 `code`. 문서의 예시 응답과 실제 응답이 같은 모양인가. **부분 충족**을 충족으로 세지 마라
- **선곡 흐름** — `docs/ARCHITECTURE.md` 3절과 4절의 흐름과 같은가. 지정 곡의 우선 처리가 임베딩 방식에만 적용되는가. 중단한 곡을 검색 쿼리 안에서 빼는가, 받은 뒤에 거르는가(뒤에 거르면 k개가 안 채워진다). 이미 나온 곡을 빼지는 않는가(D-12). 쉬는 시간이 사용자와 책의 쌍마다 따로인가(D-24). 재생 시작 위치가 구간의 시작인가(D-04)
- **평가 기록의 완전성** — 선곡 응답마다 기록이 남는가. 방식, 모델, 뽑힌 이유, 후보 목록이 모두 남는가. **무음 방식과 "곡 없음"도 기록되는가.** 기록 저장이 실패하면 응답이 어떻게 되는가 — 기록 없이 곡만 나가는 경로가 있으면 실패 조건이다(`docs/ARCHITECTURE.md` 1절)
- **묶음 적재** — `docs/AI_CONTRACT.md` 5절의 검증 항목이 하나씩 구현됐는가. 하나라도 어긋나면 묶음 전체를 적재하지 않는가. 6절의 재적재 규칙(책은 새 버전으로 쌓고, 음악은 추가·갱신하고, 없는 곡은 그대로 둔다)과 같은가
- **"못 박을 것" 준수** — `docs/backlog/epic-{N}/E{N}-*.md`의 Epic 전역 제약과 각 `step*.md`의 **금지사항**이 실제로 지켜졌는가. 금지된 것을 만들었거나, 다음 Epic의 것을 미리 만들었거나, MVP에서 만들지 않기로 한 것(D-25, `docs/ARCHITECTURE.md` 1절)을 만들었는가
- **설정값** — `docs/CONFIGURATION.md` 3절의 뜻과 기본값이 코드와 같은가. 문서에 "필수"인 값에 코드가 기본값을 주는가
- **용어 혼동** — 곡·구간·장면·문장을 코드가 뒤섞어 부르는가(`docs/GLOSSARY.md`). 같은 것을 두 이름으로 부르면 다음 step이 어느 쪽을 만들 차례인지 혼동한다
- **문서와 코드의 어긋남** — 코드가 문서와 다르게 동작하는 자리를 찾으면, 어느 쪽이 틀렸다고 단정하지 말고 어긋남 자체를 올려라. 뒤 step이 그 문서를 근거로 삼는다

**전례**

- 아직 없다.

**보지 않는 것** — 코드 내부 오류(correctness), 파일 배치(architecture). 선곡이 장면에 어울리는지, 응답 시간, 부하 같은 **감각·계측 항목은 판정하지 마라** — 안 재고 적으면 리뷰 전체가 무의미해진다.
